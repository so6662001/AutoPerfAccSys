# 06 · 实施路径、迭代规划与风险

> 说明：按功能范围与依赖关系分期，不做日历工期估算。每期以"可独立交付、可验证价值"为切分标准。

---

## 一、分期建设路线

### 阶段一：MVP（打通"数据→核算→出单"主链路）
**目标**：先让一类业务能自动算出、算对、可追溯。

- 数据集成：ERP 单一适配器（优先文件导入/DB 直连），标准中间库落地。
- 主数据：组织/岗位/员工/品规。
- 指标：日均库存/应收、周转率、挂价利润、业务净利润（先不含复杂成本重估）。
- 规则引擎：绩效方案 + 公式引擎 + 系数档 + 阶梯表（基础能力）。
- 核算：销售现货 + 采购基础绩效 的月度跑批 + 个人绩效单 + 下钻。
- 审批：主管审核 + 员工确认。

**验收**：选 1 个部门，用系统结果与历史 Excel 结果比对，差异可解释。

### 阶段二：专业能力增强
- 行情平台对接（钢银/钢之家）+ 行情价匹配引擎。
- 采购价格竞争力、行情掌控（择时收益）评分。
- 成本重估引擎（含剔除市场自然波动收益）。
- 综合奖金系数、应付/预付结构健康度。
- 销售零调、直发/民调业务净利润分成。
- 应收账款考核（扣款 + 利息两模式）。
- 行政奖惩、考勤对接。

### 阶段三：运营与规模化
- 申诉复核闭环、审计与合规强化。
- 全量看板与绩效成本分析。
- 多 ERP 适配器、多组织/多主体。
- 规则模板库、版本对比、灰度试算。

### 阶段四（远期可选）
- 行情预测辅助、绩效模拟与政策沙盘（"改系数看影响"）。
- 更多岗位（财务、管理、生产）绩效扩展。

---

## 二、MVP 范围界定（明确取舍）

| 纳入 MVP | 暂缓 |
| --- | --- |
| 现货销售提成、采购基础绩效 | 成本重估、行情择时 |
| 手工导入行情价 | 行情平台自动对接 |
| 日均库存/应收、周转率 | 应付预付结构健康度 |
| 基础绩效系数 + 阶梯提成 | 综合奖金系数联动 |
| 主管审核 + 员工确认 | 申诉复核全流程 |

---

## 三、关键风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| ERP 数据质量差/口径不一 | 核算不准，信任崩塌 | 数据就绪校验 + 质量监控；标准中间库统一口径；缺数告警不静默 |
| 成本重估口径难达成共识 | 采购超额奖争议 | 提供多种可配置方法；先试算对比；业务确认后固化 |
| 行情价与 ERP 品规匹配不上 | 价格竞争力无法算 | 品规别名映射表 + 就近/回退策略 + 人工补录 |
| 定性指标主观、易扯皮 | 基础绩效争议 | 评分卡明确维度权重 + 系统辅助定量 + 留痕 |
| 规则频繁调整 | 版本混乱、历史不可复算 | 规则强制版本化，历史按当时版本复算 |
| 薪酬数据泄露 | 合规与信任风险 | 字段级权限 + 脱敏 + 审计 + 双人复核 |
| 业务不认同结果 | 系统被弃用 | 全程可下钻追溯；上线期与 Excel 并行比对 |
| ERP 接口不稳定/无 API | 集成受阻 | 适配器多形态兜底（文件导入）；中间库解耦 |

## 四、成功衡量（上线后）

- 核算工时下降比例、出数周期。
- 核算差错率、申诉率与申诉解决率。
- 规则自助配置占比（无需研发介入的调整比例）。
- 业务满意度（采购/销售/HR）。

---

## 五、总结

本方案围绕两条主线落地钢铁行业绩效核算：

1. **取数/指标引擎**：把 ERP + 行情 + 考勤数据标准化，自动产出日均库存/应收、周转率、挂价利润、净利润、成本重估等专业指标。
2. **规则/核算引擎**：以"绩效方案 + 公式 + 系数档 + 阶梯/分成 + 奖惩"的可配置组合，覆盖采购（价格竞争力/行情掌控/存货资金效率/超额奖/综合系数）与销售（现货/零调/直发民调/应收考核）的全部核算诉求。

配合"全程可追溯 + 规则版本化 + 敏感数据保护"，实现**算得对、算得快、算得服**的产品目标。建议以 MVP 快速验证主链路，再逐步叠加行情对接与成本重估等专业能力。
