# 11 · 平台基础能力整体设计（四客户合并）

> 结合 超扑越 / 岳洋通 / 信桥 / 名亿 四家真实钢贸客户方案，抽象出一套**平台基础能力**：把各家差异收敛为"配置 + 少量专项"，使系统以配置方式适配大多数钢贸客户。

---

## 一、设计总纲

**一句话**：绩效 = Σ 核算项；每个核算项 = **取数（在某作用域下、按某计量口径，经目标单/SQL 得到值）→ 计算（阶梯/门槛/阶跃/封顶/系数/成本）→ 汇总（个人/团队、跨期）**，全程可配置、可追溯、可治理。

```
┌────────────────────────────────────────────────────────────┐
│                      绩效方案（核算项组合）                    │
├───────────────┬───────────────┬───────────────┬────────────┤
│  ① 取数层      │  ② 计算层      │  ③ 汇总层      │  ④ 治理层   │
│ ·多维作用域    │ ·阶梯/门槛     │ ·个人/团队     │ ·目标单     │
│ ·计量口径      │  /阶跃/封顶    │  (GROUP BY)    │ ·发布串签   │
│ ·成本口径      │ ·达成率映射    │ ·跨期引用      │ ·灰度/审计  │
│ ·取数DSL→SQL   │ ·系数/计息     │ ·条件豁免      │ ·明细追溯   │
└───────────────┴───────────────┴───────────────┴────────────┘
```

## 三、关键能力的落地模型

### 能力2 · 多维参数作用域引擎
```
参数(如"吨位单价") 定义在若干作用域上，运行时按最具体优先：
  默认 → 时间段 → 业务类型 → 仓库/库别 → 材质 → 品类 → 供应商 → 组织(分支) → 岗位
匹配示例（信桥）：现货·常规材质·10天内 → 9 元/吨；40-50天 → −5 元/吨
匹配示例（岳洋通）：华东分支·板材·配货库 → 1.5 元/吨（覆盖默认 1）
```

### 能力4 · 阶梯/门槛/阶跃/封顶
```
STEP(值, 阶梯表, 模式=整体档位|累进)           // 名亿累进 / 超扑越淡旺季
THRESHOLD(差价, 门槛=10|20)                     // 信桥/岳洋通门槛
STAIR(差价, 步长=10)                             // 岳洋通 (差价−10)/10
CAP(吨利润, 上限=50)                             // 信桥吨利润封顶
```

### 能力6 · 成本口径引擎
```
成本 = f(结算方式)：现款 → 销量×50 | 欠款 → 0 | 垫资 → −200      // 名亿
成本 = 一票制成本                                                // 信桥
毛利调整 = 毛利 − 返利 − 其他收支                                 // 名亿/超扑越
```

### 能力7 · 取数 DSL → SQL（名亿驱动）
```
绩效目标单：{ 指标, 起始目标, 截止目标, 单价/公式, 使用条件, 应用范围 }
金额公式 →（员工ID + 使用条件 + 应用范围）→ 编译 SQL → 返回金额
成本公式 → 拆解指标 → 运算累计成本
核算对象：GROUP BY 员工 | 部门
输出：提成核算单明细
```

### 能力11 · 明细级 × 期间级关联（名亿"问题"的解法）
```
明细级：逐单提成 = 阶梯/差价/吨位（可下钻到单据）
期间级：日均应收 / 应收周转率（期间快照聚合，属"一个总值"）
关联：期间级作为"系数/调整项"作用于明细汇总，而非逐单摊派
     个人绩效 = Σ明细提成 × 期间系数(如周转率达标系数) − 期间计息扣减
```

## 四、开发优先级（平台地基）

- **P0（先做，四客户共用地基）**：① 核算项引擎、② 多维参数作用域、③ 计量口径、④ 阶梯门槛阶跃封顶、⑤ 达成率映射、⑥ 成本口径。
- **P1（强需求，跨客户复用）**：⑦ 取数 DSL→SQL、⑧ 条件豁免、⑪ 明细×期间关联。
- **P2（专项，按客户排期）**：⑨ 合同滚动计息、⑩ 激励专项（新户/过磅/加工费）。

> 结论：四家客户 **90% 的差异**都被上述 **P0 六项 + P1 三项** 通用能力吸收；只剩 计息扩展、过磅、新户/加工费 等少量专项。把 P0/P1 做成可视化配置，平台即具备"以配置吃下钢贸客户"的基础能力。原型见 `prototype/platform-capability.html` 等平台能力页。
