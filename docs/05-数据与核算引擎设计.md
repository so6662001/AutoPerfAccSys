# 04 · 数据取数引擎与核算引擎设计

本篇是系统的"技术内核"，回应需求中最核心的两点：**取数逻辑可定义** 与 **核算公式可配置**。

---

## 一、数据集成与取数

### 1.1 数据源盘点

| 数据源 | 提供数据 | 接入方式 | 频率 |
| --- | --- | --- | --- |
| ERP | 采购/销售单据、库存、应收/应付/预付、挂牌价、成本、毛利 | API / 数据库直连 / 文件导出 | 每日 + 月末 |
| 行情平台（钢银/钢之家） | 品规行情价序列 | 平台 API / 人工导入 | 每日 |
| 考勤系统 | 出勤、迟到早退 | API / 文件 | 每日/月度 |
| 奖惩录入 | 纪律罚款、临时奖惩 | 系统内录入 | 按需 |
| 主数据 | 钢材品规、组织、岗位、员工 | 初始化 + 增量 | 按需 |

### 1.2 三层数据分层（解耦 ERP 差异）

```
ODS 贴源层  ── 原样落地各源系统数据（不清洗）
   ↓ 标准化/清洗/维度对齐
DWD 标准中间库 ── 平台统一业务模型(采购单/销售单/库存快照/应收快照/行情价)
   ↓ 指标计算
DWS 指标结果库 ── 日均库存/应收、周转率、挂价利润、净利润、成本重估
   ↓ 核算引擎
ADS 绩效结果库 ── 个人/团队绩效单、明细、系数、奖惩
```

> 通过"ERP 适配器 → 标准中间库"，核算引擎只面向标准模型，更换/升级 ERP 不影响上层规则。

### 1.3 取数引擎（Data DSL）

取数逻辑以**可视化配置 + 表达式**定义，避免硬编码。核心配置对象"取数规则"：

```yaml
取数规则:
  编码: METRIC_DAILY_INVENTORY
  名称: 日均库存
  来源表: dwd_inventory_snapshot     # 标准中间库
  过滤条件: org = :部门 AND biz_date BETWEEN :期初 AND :期末
  分组维度: [员工, 品规]              # 可选
  聚合方式: AVG(qty)                  # 日均 = 每日快照求均值
  参数: [部门, 期初, 期末]
```

- 支持函数：SUM / AVG / COUNT / MAX / MIN / 日均(按快照天数)、区间查表、条件表达式。
- 每条指标的取数口径集中管理、版本化，做到"口径唯一"。

### 1.4 关键指标计算（平台自动完成）

**日均库存 & 存货周转率**

```
日均库存    = AVG(每日库存快照 qty)              // 每日取一次库存快照
存货周转率  = 期间销售量 / 日均库存
存货周转天数 = 考核期天数 / 存货周转率
```

**日均应收 & 应收周转率**

```
日均应收    = AVG(每日应收快照 amount)           // 每日取一次应收快照
应收周转率  = 期间销售额 / 日均应收
应收周转天数 = 考核期天数 / 应收周转率
```

> 需求明确："日均库存/应收每日提取，周转率由平台自动核算。" 因此需建立**每日快照采集任务（定时调度）**，是这两个指标准确的前提。

**挂价利润归集**：从销售单取 (成交价 − 挂牌价) × 吨位。
**业务净利润归集**：按业务/项目维度汇总 毛利 + 其他收入 − 其他支出。
**成本重估**：按配置的成本基准法（移动加权/市场基准/批次）计算，并剥离市场自然波动收益（见采购篇 3.3）。

**回款账期维度归集（逐单）**：销售单需带"约定回款账期"字段，核算时按每笔业务的账期档匹配吨位单价/提成系数（见销售篇 3.4）。账期缺失时按默认档或告警补录。

**预收/预付/应收/应付计息（每日快照 → 计息）**：

```
预收计息收益 = Σ_每日(预收余额 × 日利率)            // 销售侧正向
应收逾期利息 = Σ_每日(逾期应收余额 × 日利率)         // 销售侧扣减
预付计息扣减 = Σ_每日(预付余额 × 日利率)            // 采购侧扣减
应付计息收益 = Σ_每日(应付余额 × 日利率)  (可选)     // 采购侧正向
```

> 采用"每日余额 × 日利率"逐日累加，天然处理占用天数变化，比"金额×天数"更精确。日利率、起算阈值、封顶均为可配置参数。

## 二、行情价匹配引擎

采购价格竞争力 / 行情掌控依赖行情基准价，需解决"用哪条行情价对齐哪笔采购"。

```
匹配维度：品名 × 规格 × 材质 × 地区 × 日期
匹配策略（可配置）：
  1) 精确匹配品规 + 同日行情价
  2) 日期就近（取采购日或最近交易日）
  3) 地区回退（本地无价 → 取区域基准/全国基准）
  4) 品规映射表（ERP 品规 ↔ 行情平台品规 别名映射）
```

- **品规主数据 + 别名映射**是关键：ERP 与行情平台命名不一致，需维护映射。
- 行情价缺失时：告警 + 允许人工补录，不静默跳过。

## 三、核算引擎（Performance Engine）

### 3.1 绩效方案（Plan）模型

一个"绩效方案"= 适用范围 + 若干"核算项" + 系数规则 + 生效期。

```
绩效方案(Plan)
 ├─ 适用范围：岗位/部门/人员 + 生效周期(月)
 ├─ 核算项(Component)[]        // 基础绩效、超额奖、各类提成、应收扣减、奖惩
 │    ├─ 类型：固定/公式/阶梯/系数/分成/扣减
 │    ├─ 依赖指标：引用 DWS 指标 或 其他核算项
 │    └─ 公式：由公式引擎解析
 ├─ 系数规则：基础绩效系数、综合奖金系数(达成率→档位映射)
 └─ 汇总公式：各核算项如何合成最终应发
```

### 3.2 公式引擎能力

| 能力 | 说明 | 示例 |
| --- | --- | --- |
| 四则/括号 | 基本运算 | `基数 * 系数` |
| 变量引用 | 引用指标/参数/其他核算项 | `${挂价利润} * ${分配系数}` |
| 条件分支 | IF/CASE | `IF(达成率<0.6, 0, ...)` |
| 阶梯查表 | 分段累进/整体 | `STEP(销量, 阶梯表)` |
| 区间映射 | 达成率→系数 | `LOOKUP(完成率, 系数档表)` |
| 聚合 | SUM/AVG/日均 | `AVG(库存快照)` |
| 取整/封顶 | 舍入、上下限 | `MIN(收益,封顶)`、`ROUND(x,2)` |

- 公式在配置时做**语法/依赖校验**，跑批时按依赖拓扑排序计算。
- 每个公式绑定版本，历史核算按当时版本复算。

### 3.3 系数 / 档位引擎

```
系数档配置（示例，可增删档位）：
  基础绩效系数档：0 / 0.6 / 0.8 / 1.0 / 1.2
  映射来源：评分卡得分区间 或 达成率区间
  综合奖金系数：由基础量完成率映射，作用于"基础绩效+超额奖"整体
联动规则：
  最终应发 = (基础绩效工资 + 超额奖) × 综合奖金系数 + 奖惩
```

### 3.4 行政奖惩

```
奖惩项 = 纪律罚款 + 考勤扣款 + 临时奖励
  · 纪律违规：按事件录入罚款金额
  · 考勤：迟到/早退次数 × 单次扣款 或 按考勤系统规则
  · 直接加/减到最终应发（是否受系数影响可配置，默认不受）
```

## 四、核算跑批流程

```
① 数据就绪校验   → 检查当期快照完整性/行情价覆盖率/单据封账状态
② 指标计算       → 生成 DWS 指标(周转率/挂价利润/净利润/成本重估)
③ 逐人核算       → 按方案计算各核算项 → 系数调节 → 奖惩合成
④ 生成绩效单     → 写 ADS，保存"数据快照+规则版本+计算明细"
⑤ 异常与告警     → 缺数/负值/超阈值 标记待处理
⑥ 提交审批       → 主管审核 → 员工确认 → 申诉复核 → 核定
⑦ 归档/导出      → 对接薪酬发放系统
```

- **可复算**：重跑时基于当时快照与规则版本，结果一致、可比对差异。
- **调度**：日快照任务（每日）、月度核算任务（月末触发/手动触发）。

## 五、可追溯性设计（核心公信力）

每张个人绩效单支持逐层下钻：

```
最终应发
 └─ 核算项(如"超额奖 26400")
     └─ 公式与变量值(能力性收益60万 × 阶梯 × 分配0.8)
         └─ 依赖指标(成本重估、行情波动利润)
             └─ 原始单据/快照(ERP 采购单号、行情价样本、库存快照日期)
     └─ 所用规则版本(方案v3, 公式v2, 系数表v1)
```

> 这解决"绩效不透明易争议"的痛点：任何一个数字都能回答"从哪来、怎么算、用哪版规则"。
