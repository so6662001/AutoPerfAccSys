# 01 · 产品方案总览与整体架构

---

## 一、产品定位与目标

### 1.1 产品定位

> **钢铁行业绩效核算中台**：以 ERP 及行情数据为输入，以"可配置的取数规则 + 核算规则"为引擎，输出岗位/个人的绩效工资、变动激励与奖惩结果，并支撑审批、发放与复盘的一体化平台。

它**不是**：不是重新做一套 ERP，不替代考勤/薪酬发放系统。
它**是**：横向拉通多系统数据、纵向沉淀绩效规则的"计算与核定"中枢。

### 1.2 产品目标（分层）

| 层次 | 目标 | 可衡量指标（示例） |
| --- | --- | --- |
| 效率 | 绩效核算自动化 | 月度核算工时下降 ≥ 80%，出数周期 ≤ 1 天 |
| 质量 | 口径统一、可复算 | 核算差错率 ≈ 0，100% 可逐笔追溯 |
| 敏捷 | 规则自助配置 | 政策调整无需开发，配置生效即可 |
| 公信 | 结果透明可申诉 | 争议处理有据可查，申诉闭环 |

### 1.3 目标用户与角色

| 角色 | 诉求 | 系统内定位 |
| --- | --- | --- |
| 采购员 / 销售员 | 看清自己的绩效构成与结果 | 结果查看、申诉 |
| 采购/销售主管 | 团队绩效、定性打分、审核 | 打分、初审 |
| HR / 绩效专员 | 配置规则、跑批、核定、发放 | 核心操作者 |
| 财务 | 数据口径、发放对账（一期非重点） | 数据校核 |
| 管理层 | 全局绩效洞察、成本效益 | 看板决策 |
| 系统管理员 | 数据源、权限、主数据 | 平台运维 |

## 二、设计原则

1. **配置优于开发**：取数逻辑、公式、系数、奖惩规则全部可视化配置并版本化，业务政策调整不依赖研发。
2. **口径唯一、可追溯**：任一绩效数字都能下钻到原始单据 + 所用规则版本 + 计算过程，支持"复算"。
3. **数据与规则解耦**：ERP 数据经"接入层"标准化落入中间库，核算引擎只面向标准模型，屏蔽底层 ERP 差异。
4. **岗位模型可扩展**：采购、销售是首批落地岗位，引擎抽象为"通用绩效方案"，未来可扩展至其他岗位。
5. **专业内核沉淀**：行情价匹配、周转率、重估成本等钢铁行业专有算法作为平台内核能力沉淀，成为差异化壁垒。
6. **安全合规**：薪酬绩效为敏感数据，字段级权限、脱敏、操作审计为默认能力。

### 关键内核组件说明

- **取数引擎（Data DSL）**：以可配置表达式定义"从哪张标准表、按什么过滤、取什么字段、如何聚合"，把 ERP 字段映射为绩效指标。是"取数逻辑可配置"的载体。
- **公式引擎**：支持四则运算、条件分支、阶梯查表、区间匹配、聚合函数（SUM/AVG/日均）、变量引用（指标/参数/系数），把绩效计算沉淀为可编辑公式。
- **系数/档位引擎**：管理 0~1.2 系数档、达成率→系数映射、综合奖金系数的联动逻辑。
- **行情价匹配引擎**：按品名/规格/材质/地区/时间维度，将成交价与行情价基准对齐。
- **周转率引擎**：基于每日快照计算日均库存/应收，自动产出周转率。
- **成本重估引擎**：按可选口径（移动加权/市场基准/批次）重估成本，剥离偶然性收益。

## 五、核心业务链路（端到端）

```
① 数据采集        ② 指标计算         ③ 绩效核算        ④ 核定发放
─────────────    ─────────────     ─────────────    ─────────────
ERP/行情/考勤  →  日均库存/应收   →  按方案套规则   →  跑批出结果
每日/实时同步     周转率/挂价利润    基础绩效×系数     主管审核
落标准中间库      成本重估/损益归集  超额奖/提成       员工确认/申诉
                                    奖惩加减          归档→发放系统
                                          │
                                          ▼
                          全程留痕：规则版本 + 计算明细 + 数据快照
```

**月度核算示例流程**：

1. 月末系统自动完成当月每日库存/应收快照聚合 → 生成日均与周转率。
2. 归集当月采购/销售单据 → 计算挂价利润、业务净利润、成本重估。
3. 核算引擎按"采购方案/销售方案"逐人跑批：基础绩效 → 变动激励 → 系数调节 → 奖惩。
4. 生成"个人绩效单"（含明细与下钻），推送主管审核。
5. 员工查看/确认，异议走申诉复核。
6. 核定后归档，导出/对接薪酬发放系统。

## 六、方案范围与非目标

**一期范围（MVP）**：采购、销售两岗位；ERP 数据接入 + 文件导入行情价；核心指标（周转率、挂价利润、净利润）；基础绩效系数 + 提成/超额奖 + 奖惩；核算跑批 + 结果查询 + 审批。

**非目标（本阶段不做）**：财务岗位绩效（明确非重点）、薪酬发放本身、复杂 BI 自助分析、AI 行情预测（可作远期）。
