# 00 · 需求分析与梳理

本篇对已收集到的原始需求做产品视角的解读、结构化整理、痛点与缺口识别，并统一术语口径，作为后续方案设计的输入。

---

## 一、需求本质解读

原始需求描述的是一个"**钢铁企业绩效核算的自动化**"诉求，本质上要解决三个层面的问题：

1. **算得对**：钢铁贸易的薪酬结构复杂（基础绩效 + 提成/超额奖 + 系数调节 + 奖惩），且强依赖行情价、库存周转、应收周转等专业指标，手工核算易错、口径不统一。
2. **算得快**：数据分散在 ERP、行情平台（钢银、钢之家）、考勤系统中，每月核算依赖人工从多系统取数、拼表、套公式，效率低、周期长。
3. **算得服**：绩效结果需要"可解释、可追溯、可申诉"。采购/销售是与钱强相关的岗位，核算逻辑必须透明，否则会引发内部争议。

> **一句话定义产品**：一个"**规则可配置、数据自动采集、核算自动跑批、结果可追溯**"的钢铁行业绩效核算引擎。

## 二、需求结构化拆解

将原始需求拆解为 6 大领域、可落地的功能项：

### 领域 1：采购绩效核算
| 需求点 | 关键要素 | 可核算性 |
| --- | --- | --- |
| 采购价格竞争力 | 日常进价 vs 市场同期价 | 需外部行情价基准 |
| 行情掌控能力 | 对上游后续行情涨跌的判断 | 需行情价历史序列 |
| 存货与资金效率 | 存货周转率、应付/预付结构合理性 | 需 ERP 库存与往来数据 |
| **预付账款计息**（补充） | 预付占用公司资金 → 资金成本扣减（应付可作正向） | 需预付/应付每日快照 + 日利率 |
| 超额奖（提成） | 行情波动利润 + 实际购销盈亏 + 其他业务收益 | 需重估成本、剔除偶然性收益 |
| 综合奖金系数 | 基础量完成度决定 0~1.2 系数 | 需基础量目标与实际 |

### 领域 2：销售绩效核算
| 需求点 | 关键要素 | 可核算性 |
| --- | --- | --- |
| 基础绩效 | 保底销量、新客开发、客户维护、客情 | 部分定量、部分定性打分 |
| 现货销售提成 | 吨位固定提成（阶梯）+ 挂价利润分配 | 需挂牌价、成交价、吨位、分配系数 |
| 零调业务提成 | 按净利润（毛利+其他收入-其他支出）分成 | 需业务级损益归集 |
| 直发/民调业务 | 逻辑同零调，系数不同 | 需业务类型区分 |
| **回款账期差异化提成**（补充） | 每笔业务回款账期不同 → 吨位提成单价/提成系数不同 | 需销售单带约定回款账期，按账期分档计提 |
| 应收账款考核 | 扣款模式 / 利息核算模式 | 需回款天数、逾期天数 |
| **预收账款计息**（补充） | 预收占用资金给予正向计息激励 | 需预收每日快照 + 日利率 |

### 领域 3：数据取数与指标计算
- ERP 为唯一业务数据源（挂价毛利、应收、库存等）。
- 日均库存：每日快照 → 期间日均 → 结合销量算存货周转率。
- 日均应收：每日快照 → 期间日均 → 结合销售额算应收周转率。
- 行情价：支持人工导入 + 平台对接（钢银、钢之家）。

### 领域 4：绩效规则与系数配置
- 基础绩效系数档：0 / 0.6 / 0.8 / 1.0 / 1.2。
- 最终绩效工资 = 基数 × 系数。
- 综合奖金系数：基础量不足时对绩效+超额奖整体打折。
- 各类分配系数、阶梯提成规则、分成比例可配置。

### 领域 5：行政奖惩
- 纪律违规罚款。
- 考勤（迟到、早退）扣奖金。

### 领域 6：核算结果、审批与发放
- 隐含需求：核算结果需要复核、审批、归档、下发到个人。
- （原文未明确，属于产品必须补齐的闭环环节。）

## 三、痛点与价值假设

| 现状痛点 | 系统价值 |
| --- | --- |
| 多系统取数、人工拼表，月度核算耗时长 | 自动跑批，核算周期从"数天"压缩到"分钟级" |
| Excel 公式版本混乱、口径不统一 | 规则中心化配置，全公司统一口径 |
| 行情价靠人工查、易滞后 | 对接钢银/钢之家，行情价自动入库 |
| 绩效结果不透明、易争议 | 核算过程留痕，支持逐笔下钻与复算 |
| 政策调整（系数、比例）改动成本高 | 规则可视化配置，业务侧自助调整、版本化管理 |

## 四、需求缺口与澄清项（设计中已做合理假设）

原始需求偏"业务口径描述"，落地为系统还有以下关键缺口。方案中我按行业通行做法给出**默认设计假设**，标注 🔶，待与业务方确认。

1. **考核周期**：未明确按月/季/半年。🔶 假设**月度为核算主周期**，支持季度/年度汇总与年终奖清算。
2. **重估成本口径（采购超额奖核心难点）**：需"重新评估成本价格、排除偶然性收益"，但未定义算法。🔶 提供多种可配置的成本基准法（移动加权平均、市场基准价、批次成本），由业务选择。详见采购篇。
3. **行情价基准的匹配维度**：价格对比需要匹配"品名/规格/材质/地区/时间"。🔶 设计标准化"钢材品规主数据 + 行情价基准表"，按维度匹配。
4. **定性指标的量化**：新客开发、客户维护、客情、行情掌控判断能力等含主观成分。🔶 设计"评分卡 + 上级打分/系统辅助指标"混合模式。
5. **超额奖与提成的关系**：采购侧"超额奖=提成"，销售侧"提成/奖金"并列。🔶 统一抽象为"**变动激励**"，采购与销售是同一引擎的不同规则集。
6. **应付/预付结构"合格"判定标准**：原文仅举例。🔶 设计为可配置的"结构健康度规则"（阈值/区间/评分）。
7. **数据颗粒度**：绩效归属到"人"还是"团队/岗位"？🔶 支持"个人 + 团队"两级，业务/单据可归属到责任人。
8. **争议与申诉**：绩效结果的申诉流程未提及。🔶 补齐核算结果的确认、申诉、复核闭环。
9. **权限与保密**：薪酬数据高度敏感。🔶 补齐字段级权限与数据脱敏设计。
10. **ERP 具体系统与接口形态**：未指明用友/金蝶/管家婆/自研等。🔶 设计"适配器 + 中间库"解耦，支持 API/数据库直连/文件导入多形态。

## 五、统一术语表（口径对齐）

| 术语 | 定义 |
| --- | --- |
| 绩效基数 | 岗位对应的绩效工资基准金额，系数调节的乘数基础 |
| 基础绩效系数 | 反映基础工作完成度的档位系数（0 / 0.6 / 0.8 / 1.0 / 1.2） |
| 综合奖金系数 | 当基础业务量不足时，对"绩效+超额奖"整体打折的系数（可 <1.0 甚至为 0） |
| 超额奖 / 变动激励 | 基于经济收益（利润、提成）计算的浮动奖励 |
| 挂牌价（挂价） | 企业对外公示的销售基准价 |
| 挂价利润 | (成交价 − 挂牌价) × 成交吨位，衡量销售议价溢价 |
| 行情价基准 | 来自钢银/钢之家或人工导入的市场参考价，用于采购价格竞争力评判 |
| 重估成本 | 剔除偶然性因素后，用于衡量采购真实能力的成本口径 |
| 日均库存 | 期间内每日库存快照的算术平均 |
| 存货周转率 | 期间销量（或销售成本）/ 日均库存 |
| 日均应收 | 期间内每日应收账款快照的算术平均 |
| 应收周转率 | 期间销售额 / 日均应收 |
| 零调业务 | 零星调剂/贸易撮合类业务，按净利润分成 |
| 直发/民调业务 | 货物由上游直接发运给客户等业务类型，核算逻辑同零调、系数不同 |
| 现货销售 | 有库存实物的销售业务，含基础量提成 + 挂价利润 |

## 六、结论

需求整体清晰、行业针对性强，核心难点集中在两处：

1. **专业指标的"取数与计算口径"**（重估成本、行情价匹配、周转率、结构健康度）——这是系统的技术护城河。
2. **绩效规则的"可配置化"**（系数档、阶梯、分成比例、奖惩规则）——这是系统能否长期适配业务政策调整的关键。

因此，产品设计的两条主线定为：**① 强大的取数/指标引擎；② 灵活的规则/公式配置引擎**。下一篇给出总体方案与架构。
